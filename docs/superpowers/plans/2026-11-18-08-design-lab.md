# Match the Design Lab — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The desktop app's Chats screens look and behave like the design lab's app window (`docs/design/ion-design-lab.html`, `#win`): the same layout, components, spacing and type. Nothing in the lab is faked: a part ion can't back yet is left out and listed.

**Architecture:**
- **The lab's CSS is the source.** The rules for the app window are copied from the lab's `<style>` into `packages/design-system/src/lab.css`, unchanged except for selectors scoped to the app.
- **The app's markup uses the lab's class structure:** `.win > .rail + .body > .mode.chats > .side + .chat`, `.head`, `.split > .convo + .tools`, `.msgs > .col > .u / .a`, `.foot > .await + .cbox`, `.work`, `.bpop`, `.panel .code .fh .ln`.
- **The lab's canvas avatars** (its `shapePath` and `drawBot` code) move to design-system `Avatar`.
- **The data stays the daemon's:** the reducer from Plan 07 feeds the new markup.
- **Each screen is checked by eye:** a Playwright screenshot of the lab and of the app at 1440×900, with every difference listed in the ledger and fixed.

**Tech Stack:** As Plan 07; no new dependencies.

## Global Constraints

- **Copy the lab exactly:** the same text, icons (Lucide names as in the lab), sizes, colours, radii, spacing and fonts. Where the lab and Plans 05–07 differ, Plans 05–07 win only where this plan says so below.
- **Kept from Plans 05–07 (the lab has none of these), drawn in the lab's own components:**
  - **Access:** a `.pill` beside the brain pill: "Auto" or "Full access".
  - **Questions:** the lab's one-line `.await` bar (see "A quiet chat" below).
  - **Tool input and output:** inside the `.work` step, as the lab's `.wg` code lines, expandable.
  - **Denials:** a muted inline line (see "A quiet chat").
- **A quiet chat** (the user, 2026-11-18: "make chat quiet", no unnecessary text hints):
  - **The question bar is small**, like the lab's one-line `.await`: the question and the option buttons. Its details (why, each option's reasoning, your own words, "Always for this project") open from a chevron and are closed by default. It never covers the conversation.
  - **A blocked tool call** is a subtle inline line in the conversation (the lab's muted `.wn` size and colour, with a small `--wait` mark), not a banner. When ion stops waiting for your answer, the line changes quietly: no explanatory sentence.
  - **Errors** are subtle inline lines: muted, small, the message only. No codes, and no red blocks unless the run failed.
  - **Retries count down live:** "Retrying in 4s", 3s, 2s… then nothing once the retry starts.
  - **No coloured side stripes:** no `border-left` (or any one-side) accent on cards, questions, warnings, notices or lines. Status shows only as the lab does it: a small dot or icon, or text colour.
  - **No hint text anywhere:** no "Answer: …", "Nothing more to show", "Your answer still counts" or "No changes yet"-style lines. Empty states are empty, as in the lab. Placeholders only where the lab has them ("Reply…", "Ask anything, or describe a change…").
- **Left out until they're real** (listed in `apps/desktop/README.md`):
  - the Library button, attachments (paperclip, `.catt`, `.att`), media thumbs and `.proof`;
  - Preview, Terminal and Viewer tabs; "Open in editor"; Share and More;
  - the Ions and Settings rail buttons, Search and ⌘K, the ghost (temporary chat).
- **The Files tab is real:** the changed files from `chat.diff`, as the lab's `.tree`.
- **Walls and rules as Plan 07:** no `node:*`, `fetch` or storage in the UI; the UI only displays state.

## Review Focus

1. **A long chat (hundreds of steps)** stays responsive with the `.work` blocks: memoised as in Plan 07. Test in Task 4.
2. **Text from an agent inside lab components** (step names, code arguments, file paths, option text) is always text, never HTML. Test in Task 4: `<img onerror>` in a tool argument renders as text.
3. **The brain popover with an agent that's signed out, or one with no model list:** shows it "not ready", and Send stays disabled. Test in Task 5.
4. **The window narrower than the lab (900 px):** the side panel collapses, as the lab's `.split.solo`, and nothing overflows. Check in Task 7.
5. **Light theme:** the lab is dark only, so the app stays dark. This is listed, not built.
