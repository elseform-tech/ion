# Every Tool Call Through ion — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every tool call any agent makes goes through ion first; agents ask you instead of being approved; every thread lives in a project.

**Architecture:**
- **The gate.** Each harness's own "before a tool runs" hook reports the call to the daemon at `/gate/<key>` (loopback, a key per run). The hooks are:
  - Claude Code: an SDK `hooks.PreToolUse` callback;
  - Grok: a `PreToolUse` HTTP hook file in the chat's worktree;
  - opencode: a plugin ion ships, loaded through `OPENCODE_CONFIG_CONTENT`.
  - The daemon answers with the same decision path as today: policy, then Full access, then Auto (rules, then the judge).
  - The harness's own permission prompts still reach ion. When the gate already allowed that call, they're answered from the gate's allow without a second record.
- **The ask tool.** ion's MCP server gains `ask`:
  - The agent asks a question with 2–4 choices, then ends its turn, and the chat waits under Needs you.
  - Your answer is stored as a decision, applying to this chat, this project or everywhere, and sent back into the chat as the next message.
  - Decisions marked "always" can be answered by ion. The judge sees your decisions, and outcomes get added to them.
- **Projects.** Every thread lives in a project.
  - Projects are made by name under `[folders] projects` (default `~/ion/projects`).
  - A built-in `default` project is used when none is picked.

**Tech Stack:** TypeScript ESM, Vitest, `@anthropic-ai/claude-agent-sdk` hooks, Grok hooks (`~/.grok/docs/user-guide/10-hooks.md`), opencode plugins, the MCP SDK.

**Spec:** `docs/design/ion-design-lab.html`, plus the user's decisions of 2026-11-18:
- "a hidden hook to audit and judge tool calls … applies the hook to all harnesses";
- "eliminating approvals and introduce ask tool instead (it will record user decision and/or consequences so that the agent can act more reliably based on past decision)";
- "every thread regardless of ion or plain chat, a project is necessary";
- "name it default";
- "/ion/projects/<name>" (taken as `~/ion/projects/<name>`).

**Live probes (2026-11-18, done before this plan):**
- **Grok `PreToolUse` hook:**
  - The global hook file fired under `grok agent stdio`, launched by ion in an untrusted worktree, and its deny stopped the built-in `cat`.
  - A hook file in the worktree fired only with `GROK_FOLDER_TRUST=0`.
  - Any global hook makes Grok ask for folder trust everywhere you use it yourself, so ion uses the worktree file.
- **opencode:** a plugin loaded through `OPENCODE_CONFIG_CONTENT` saw `{tool:"bash", args:{command}}` and blocked the call by throwing.

## Global Constraints

- **Copy:** short, plain words.
  - Chat lines stay `· Allowed by ion: …` / `· Denied by ion: … — reason`.
  - Ask lines are `· ion asked: <question>` and `· You chose: <label>`, or `· Answered by ion from your decision on <d MMM>: <label>`.
- **Fail closed.** No answer from ion (daemon down, timeout, bad reply) means the call is denied. That's Grok's `failClosed: true`, and a throw in the opencode plugin and the Claude hook. Gate timeout is 60 s (the judge's own is 30 s).
- **Gate keys:**
  - kept apart from MCP keys: same `Grants`, `kind: "gate"`;
  - a gate key only answers for its own run, and is revoked when the run ends;
  - no Origin header.
- **The hook file can't be touched in Auto.** `.grok/hooks/ion.json` in any worktree is one of ion's files to the rules: denied in Auto, whatever the tool.
- **Old data still reads:**
  - `approval.*` events;
  - `need.raised` without `choices`;
  - `need.resolved` with `decision: allow|deny`.
  - Views are rebuilt by version bump as before.
- **No real model calls in tests.** The fake harness gains a `gated` scenario that posts to the gate. Live checks use opencode and Grok; Claude Code once at the end.
- **Walls:**
  - each hook's payload is turned into an `ApprovalRequest` by its adapter (`HarnessAdapter.gateCall`);
  - the daemon never parses harness formats;
  - child processes stay in `workspace` and the adapters.

## Review Focus

1. **A harness whose hook didn't load** (opencode `--pure`, a Grok hook-load error): its permission prompts still reach ion and are decided as today, never auto-allowed. Test in Task 2: a permission request with no gate allow queued is decided in full.
2. **The agent edits or deletes `.grok/hooks/ion.json`, or reads the gate URL.**
   - The edit is denied by rule.
   - Reading the URL gives nothing: the key only answers for its own run.
   - Test in Task 3.
3. **You answer an ask after the run, or the daemon restarted.** The answer is stored and starts the follow-up run in that chat. A second answer to the same need is "That's already answered". Test in Task 4.
4. **An "always" decision that only loosely fits a new question.** ion answers only when the matcher returns one of the new question's own choice labels exactly; anything else goes to you. Test in Task 4.
5. **Two runs answered from the gate's queue out of order** (parallel tool calls): only allows are queued, so either order is correct. A deny never queues. Test in Task 2.
