# ion Adapters Implementation Plan (Plan 02)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `ion ask "…" -p <project>` runs a real Claude Code turn through the daemon and streams it back: text, thinking, tool calls, file changes, approvals decided by a simple policy, usage and the end state, all stored as ion events.

**Architecture:** `packages/adapter-kit` defines the harness contract and a shared contract-test suite. `packages/adapters/fake` replays scripted scenarios (used by every daemon and CLI test). `packages/adapters/claude-code` drives Claude Code through the Claude Agent SDK, with a pure mapper from SDK messages to ion events, tested against recorded transcripts. The daemon gains an adapter registry and a run manager; the CLI gains `ion ask`.

**Tech Stack:** as Plan 01, plus `@anthropic-ai/claude-agent-sdk` (0.3.x, bundles Claude Code 2.1.x).

**Spec:** `docs/architecture/contract.md` (adapter interface, event types, principles), `docs/design/ion-design-lab.html` (Architecture: adapters, approvals; Chats: thinking/tool umbrella). SDK reference used: https://code.claude.com/docs/en/agent-sdk/typescript.md, permissions, user-input, sessions, authentication.

## Global Constraints

- Everything from Plan 01 (Node ≥ 24, ESM, walls, health ratchet, goldens, copy rule).
- No real model calls in CI. Live tests run only with `ION_LIVE=1`.
- Adapters emit only adapter event types; `approval.resolved` and everything else daemon-only comes from the daemon (enforced by `parseEvent`).
- The daemon imports adapters only in `apps/daemon/src/adapters/registry.ts` (new lint rule in Task 8).
- ion never reads or stores credentials or account details. From `claude auth status --json` the adapter keeps only `loggedIn` and `authMethod`; it never reads `email`, `orgId`, `orgName`.
- SDK `env` replaces the child's environment: always pass `{ ...process.env, ...extra }`.
- Never use `permissionMode: "bypassPermissions"`. Permission decisions go through `canUseTool`.
- Use the user's installed `claude` binary (`pathToClaudeCodeExecutable` = resolved path), so the login, version and settings ion uses are the ones the user sees. Fall back to the SDK's bundled binary only if none is installed.
- Run `claude` without a shell (`spawn`/`execFile`, no `shell: true`), so shell functions and aliases never run.

## Open question for the user (not blocking this plan)

Anthropic's Agent SDK docs: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK." This plan only runs the user's own `claude` with whatever login the user already has, and shows the auth method in use. Before ion ships to other people, confirm with Anthropic whether a subscription login is acceptable, or default to API-key auth (`claude auth login --console`).

## Review Focus

1. **Claude Code missing or signed out** → `ion ask` prints `Claude Code isn't signed in. Run: claude auth login` (or `isn't installed`), exits 1, and leaves no run in `running`. Test in Task 9.
2. **The SDK throws mid-stream or the CLI crashes** → an `error` event, then `run.finished { status: "failed" }`; the daemon keeps serving other requests. Test in Task 7.
3. **Ctrl+C during a tool call** → `run.finished { status: "interrupted" }` within 5 s and no `claude` child process left. Test in Task 7 (fake) and Task 6 (live smoke).
4. **`ANTHROPIC_API_KEY` set in the daemon's environment** silently switches billing from subscription to API → `auth.status()` reports the method, and `ion ask` prints it on the first line (`Claude Code · API key` / `· Claude subscription`). Test in Task 4.
5. **Long answers** → 5,000 text deltas stream and store in under 2 s; the adapter coalesces deltas every 50 ms or 2 KB. Test in Task 5.

**Interfaces:**
- Produces `dataSchemas` for:

### Task 2: `@ion/adapter-kit`

**Files:**
- Create: `packages/adapter-kit/src/{index.ts,types.ts,queue.ts,contract.ts}`
- Test: `packages/adapter-kit/src/queue.test.ts`

**Interfaces:**
- Produces, exactly as `docs/architecture/contract.md`: `HarnessAdapter`, `Session`, `Capabilities` (re-exported from schema), plus:
  - `type AdapterEvent = Omit<NewEvent, "chatId" | "runId" | "origin">` — adapters don't know chat or run ids; the daemon stamps them.
  - `type StartOpts = { cwd: string; model: string | null; effort: EffortLevel | null; instructions?: string; resume?: string; signal: AbortSignal; decide: (req: ApprovalRequest) => Promise<Decision> }` where `ApprovalRequest = { requestId: string; toolId: string; toolName: string; kind: string; summary: string; input: Record<string, unknown> }` and `Decision = "allow" | "allow_always" | "deny"`. (Ruling vs. contract.md: approvals are a callback the daemon supplies, instead of `respond()` on the session; Plan 3 wires it to needs.)
  - `Session.events(): AsyncIterable<AdapterEvent>` ends after `run.finished`.
  - `createEventQueue<T>(): { push(x: T): void; end(): void; fail(e: Error): void; [Symbol.asyncIterator](): AsyncIterator<T> }`
  - `describeAdapterContract(name: string, make: () => HarnessAdapter, scenarios: ContractScenarios): void` — a Vitest suite: a turn ends with exactly one `run.finished`; `run.started` comes first; every `tool.finished` has a matching earlier `tool.started`; a denied approval never produces `file.changed` for that tool; `interrupt()` ends with `interrupted` within 5 s; no daemon-only event types; every event passes `parseEvent` once stamped.
- [ ] TDD for `createEventQueue` (order kept, `end` finishes iteration, `fail` rejects the iterator, pushes after `end` are ignored). The contract suite is exercised in Task 3.
- [ ] Update `docs/architecture/contract.md` to match: `StartOpts.decide` instead of `Session.respond`, `AdapterEvent` without chat/run ids, the `fake` adapter id.
- [ ] Commit `feat(adapter-kit): harness contract and shared contract tests`.

### Task 4: Claude Code adapter — detect, auth, capabilities

**Files:** Create `packages/adapters/claude-code/src/{index.ts,cli.ts,capabilities.ts}`; Test `src/cli.test.ts`

**Interfaces:**
- `createClaudeCodeAdapter(deps?: { exec?: Exec; query?: typeof import("@anthropic-ai/claude-agent-sdk").query; which?: (bin: string) => string | null }): HarnessAdapter` (`id: "claude-code"`). Tests inject `exec`/`which`/`query`.
- `type Exec = (file: string, args: string[]) => Promise<{ code: number; stdout: string }>`
- `detect()`: `which("claude")` resolves the real binary on `PATH` (not a shell function); `claude --version` → `{ installed, version: "2.1.326", path }`.
- `auth.status()`: `claude auth status --json`; returns `{ signedIn: loggedIn, method: label }` where label maps `claude.ai`→`Claude subscription`, `api_key`/`api_key_helper`→`API key`, `oauth_token`→`Long-lived token`, `third_party`→`Cloud provider`, else `Not signed in`. Never reads other fields. Non-zero exit → `signedIn: false`.
- `auth.login()`: runs `claude auth login` with inherited stdio.
- `capabilities()`: `effort.levels ["low","medium","high","max"]`, `nativeName: "effort"`, `canDisableThinking: true`, `thinking: "summary"`, `approvals: "interactive"`, `resume/interrupt/images/mcp/skills: true`, `usage: "cost"`; `models` from a fixed list `[{id:"opus",label:"Opus"},{id:"sonnet",label:"Sonnet"},{id:"haiku",label:"Haiku"}]` (aliases; `supportedModels()` needs a live session — Plan 5 refreshes from it).
- [ ] Tests: version parse; not installed (`which` → null) → `installed: false`; auth JSON with `loggedIn: true, authMethod: "api_key", email: "x@y"` → `{ signedIn: true, method: "API key" }` and the returned object has no `email` key; exit 1 → signed out.
- [ ] Commit `feat(adapters): Claude Code detect, auth status and capabilities`.

### Task 5: Claude Code adapter — sessions and the event mapper

**Files:** Create `packages/adapters/claude-code/src/{session.ts,map.ts,tools.ts,coalesce.ts}`; Test `src/map.test.ts`, `src/session.test.ts`, `src/coalesce.test.ts`

**Interfaces:**
- `mapSdkMessage(msg: SDKMessage, state: MapState): AdapterEvent[]` — pure. `MapState` tracks open tool ids, the session id and the model.
  - `system/init` → `run.started { harness: "claude-code", model, effort, authMethod }`
  - `stream_event` text deltas → `message.delta`; thinking deltas → `thinking.delta`
  - `assistant` text block → `message.completed`; `tool_use` → `tool.started` (`kind` from `toolKind(name)`: Read/Glob/Grep/LS→read|search, Edit/Write/MultiEdit/NotebookEdit→edit, Bash→command, WebFetch/WebSearch→web, `mcp__*`→mcp, else other; `summary` like `src/cart/totals.ts` or the command's first 80 chars)
  - `user` `tool_result` → `tool.finished { ok: !is_error }`; for edit tools also `file.changed` (path from the tool input; `added/removed` from `old_string`/`new_string` line counts when present, else null)
  - `result` → `usage.reported` (from `modelUsage`, cost `total_cost_usd`) then `run.finished` (`success`→done, `error_during_execution` after interrupt→interrupted, `error_max_budget_usd`→capped, other errors→`error` then failed)
  - unknown variants → `[]`
- `createDeltaCoalescer(flush: (text: string) => void, opts?: { ms?: number; bytes?: number })` → `{ push(text), end() }`, defaults 50 ms / 2048 bytes.
- `startSession(opts: StartOpts, deps)`: calls `query({ prompt: inputStream, options: { cwd, model, effort, thinking: { type: "adaptive", display: "summarized" }, includePartialMessages: true, resume, abortController, canUseTool, pathToClaudeCodeExecutable, env: { ...process.env }, settingSources: ["user","project","local"], systemPrompt: { type: "preset", preset: "claude_code", append: instructions } } })`. `canUseTool` → builds `ApprovalRequest` → `await opts.decide(req)` → `allow`/`deny` (`allow_always` → allow with `updatedPermissions` from `suggestions`, destination `session`). `send()` pushes an `SDKUserMessage { type: "user", message: { role: "user", content }, parent_tool_use_id: null }`. `interrupt()` → `query.interrupt()`, then abort after 3 s. A thrown error inside the loop → `error` + `run.finished failed`.
- [ ] **Step 0:** Confirm `includePartialMessages`, `effort`, `thinking.display` and the `SDKMessage` shapes against the installed SDK's `.d.ts`; ledger any difference as a ruling.
- [ ] Mapper tests table-driven from small hand-written SDK messages; coalescer tests (5,000 one-char pushes → few flushes, all text kept, total under 2 s with real timers); session tests with an injected `query` that yields scripted messages and records the options it got (`env` contains `PATH`; no `bypassPermissions`; `canUseTool` routes to `decide`).
- [ ] `describeAdapterContract("claude-code", …)` passes with the injected `query`.
- [ ] Commit `feat(adapters): Claude Code sessions mapped to ion events`.

### Task 7: Daemon — registry and run manager

**Files:** Create `apps/daemon/src/adapters/registry.ts`, `apps/daemon/src/runs/{manager.ts,policy.ts}`; Modify `apps/daemon/src/api/commands.ts`, `server.ts`; Test `apps/daemon/src/runs/manager.test.ts`

**Interfaces:**
- `registry.ts`: `getAdapter(id: string): HarnessAdapter | null` for `"claude-code"` and `"fake"` (fake only when `ION_ALLOW_FAKE=1`, which tests set).
- `policy.ts`: `decideByPolicy(req: ApprovalRequest, opts: { allowEdits: boolean; cwd: string }): Decision` — reads/searches allow; edits allow only with `allowEdits` and a path inside `cwd`; everything else deny. (Plan 3 replaces "deny" with a need.)
- `RunManager` (`new RunManager(store, registry)`): `ask(args): { chatId, runId }` — creates the chat (`chat.created`) if `chatId` is missing, refuses a second active run in the same chat (`UserError("This chat is already running")`), resolves the project path from config (missing → `UserError("Unknown project: x")`), checks `detect()`/`auth.status()` first (`UserError("Claude Code isn't installed")` / `isn't signed in. Run: claude auth login`), then starts the session in the background, stamping every adapter event with `chatId`, `runId`, `origin: "adapter"`, and appending `approval.resolved { by: "policy" }` after each decision. `interrupt(runId)`. Any throw from the adapter → `error` + `run.finished failed`.
- [ ] Tests with the fake adapter: `hello` stored in order; `approve` with `allowEdits:false` → `approval.requested`, `approval.resolved deny by policy`, no `file.changed`; `fail` → failed and the daemon still answers `status`; second `ask` on a running chat → error; `slow` + `interrupt` → `interrupted` in < 1 s; unknown project → error, no run stored.
