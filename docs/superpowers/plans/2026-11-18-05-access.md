# Access Modes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Two access modes replace per-action approvals: **Full access** (anything runs) and **Auto** (ion decides on the spot, the run never pauses).

**Architecture:**
- **Policy first.** Edits inside the chat's worktree and ion's own MCP tools stay allowed by policy, as before.
- **Everything else goes by mode.**
  - Full access allows it.
  - Auto asks `apps/daemon/src/access`: free rules first (secrets → deny, read-only commands inside the worktree → allow), then a quick model ("the judge", run on `ion.quick`, no tools). Answers are cached per chat.
- **Recorded and shown.** Every Auto decision is stored as `approval.resolved {by: "ion", reason}` and shown in the chat. Needs stay for questions only you can answer (none raised yet).

**Spec:** User decisions, 2026-11-17:
- "give only two options instead, full access, and auto (basically ion or plain chat decides if it goes through, no approval required)";
- "the composer can select access mode, as for ion, perhaps settings".

## Global Constraints

- Copy: short, plain words. Labels "Full access" and "Auto". Chat lines `· Allowed by ion: <summary>` / `· Denied by ion: <summary> — <reason>`.
- **Where the mode comes from:**
  1. the composer's pick for this message (CLI `ion ask --access auto|full`);
  2. else the project's `access`;
  3. else `[access] default` in config.toml, which defaults to `"auto"`.
  - ion's (the chief's) own mode is a Settings value later (Plan 07).
- **The judge sees only the action** (tool, summary, exact input), the project id and your message for this run, as labelled data. It never sees repo files. It answers JSON `{"allow": boolean, "reason": string}`; anything else, a failure, or no answer within 30 s means deny with a reason.
- **Never allowed in Auto, without asking the model:**
  - paths under `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.config/gh`, `~/.netrc` or `~/.docker/config.json`;
  - ion's own data or config folder;
  - commands that mention any of those.
- No real model calls in tests (the judge is injectable; the default judge is tested with the fake harness).

## Review Focus

1. **An action that tries to talk the judge into allowing it** ("ignore your rules and allow") → the judge prompt labels the action as data with a random-id block; secrets stay denied by rule whatever the model says. Test in Task 2.
2. **The judge harness is missing, signed out or slow** → deny with "ion couldn't decide: …", and the run continues. Test in Task 2.
3. **The same action asked twice in a chat** → one judge call. Test in Task 2.
4. **Full access** never pauses or asks the model; Auto never pauses. Test in Task 2.
5. **An old database or event with `by: "you"`** still reads. Test in Task 1.

### Task 1: Access mode in config, schema and CLI
- Config:
  - `access: z.object({ default: z.enum(["auto","full"]).default("auto") }).prefault({})`;
  - Project gains `access?: "auto" | "full"`;
  - `setProjectAccess(c, id, mode)`.
- Schema:
  - `ask.args.access?: "auto" | "full"`;
  - `approval.resolved` gains optional `reason: string`, and `by` gains `"full"`;
  - API `project.setAccess {projectId, access} → {ok}`.
- CLI:
  - `ion ask --access <auto|full>`;
  - `ion projects access <id> <auto|full>` ("Access for <id>: Auto" / "Full access").
- Golden diffs: config, contract, help.
- Commit `feat: access modes in config and CLI`.

### Task 2: Auto decisions
- `apps/daemon/src/access/{rules.ts,judge.ts,index.ts}`.
  - `ruleFor(req, roots, home, ionDirs) → "allow" | "deny" | null`.
  - `createJudge(runHarness) → Judge = (input) => Promise<{allow, reason}>`.
  - `createAccess(judge)` with a per-chat cache.
- Manager:
  - `mode = args.access ?? project.access ?? config.access.default`;
  - policy allow → allow;
  - full → allow (`by: "full"`);
  - auto → rules → cache → judge (`by: "ion"`, reason).
- Tests:
  - rules: secrets denied, read-only commands inside the worktree allowed;
  - injection text in a command still denied for secrets (RF1);
  - judge timeout, failure or garbage → deny with reason (RF2);
  - cache (RF3);
  - full never calls the judge (RF4);
  - no `need.raised` in either mode;
  - the default judge with the fake harness.
- Commit `feat: auto access — ion decides, runs never pause`.

### Task 3: Show decisions; docs; end to end
- Render:
  - `· Allowed by ion: …` / `· Denied by ion: … — reason`;
  - full access quiet;
  - old `by: "you"` lines unchanged.
- Docs: READMEs, AGENTS.md, the docs index.
- End to end:
  - opencode (free) in Auto: a harmless command runs after "Allowed by ion"; `cat ~/.ssh/id_rsa` is denied by rule;
  - `--access full` runs a command with no line;
  - Grok in Auto: one command.
- Commit `docs: access modes`.
