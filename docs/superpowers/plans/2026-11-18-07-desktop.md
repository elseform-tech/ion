# Desktop App and Chats Screens — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The ion desktop app: a Tauri 2 window whose Chats screen lets you start and continue chats, watch runs, answer agents' questions and see a chat's changes. It shows the daemon's state and holds none of its own.

**Architecture:**
- **`apps/desktop`:** React + TypeScript + Vite inside Tauri 2.
  - The Rust side does one thing: it reads `daemon.json` (port and token) from ion's data folder and hands it to the UI.
  - The UI talks to the daemon only through `@ion/client`'s browser entry (the WebSocket API) and imports no Node.
- **The timeline:** a pure reducer turns a chat's events into timeline items. It's tested without a browser.
- **`packages/design-system`:** the spec's tokens (`docs/design/ion-design-lab.html`, `:root`), bundled fonts, Lucide icons, and a few shared components.
- **The daemon gains one command:** `chat.diff`, for the changes panel.

**Tech Stack:** Tauri 2, React 19, Vite, TypeScript, `lucide-react`, `react-markdown` + `remark-gfm` (no raw HTML), `@fontsource/{inter,sora,jetbrains-mono}`, Vitest. Playwright is used only for the end-to-end check.

**Spec:** `docs/design/ion-design-lab.html`: the Chats screen, the tokens, the tech stack ("Desktop shell Tauri 2 … The UI only displays state"; "UI React · TypeScript · Vite · CSS-variable design tokens, Lucide icons"). The user's decisions since then:
- Plan 05: two access modes, picked in the composer;
- Plan 06: agents ask with choices instead of approvals, and every chat has a project (`default`);
- 2026-11-18: "yes to plan 07 writing and implementing".

## Global Constraints

- **The UI holds no state of its own.** Everything comes from daemon commands and events, and reconnecting re-reads it.
- **Walls:** no `node:*`, no `fetch`, no `localStorage` in `apps/desktop/src`. Imports only from `@ion/client/browser`, `@ion/schema` and `@ion/design-system`.
- **Tauri:**
  - only the `daemon_info` command is exposed;
  - no shell or fs plugins;
  - the CSP allows only `ws://127.0.0.1:*`.
- **Copy:** short, plain words.
- **Labels:**
  - sidebar sections "Needs you", "Running", "Chats";
  - access options "Auto" and "Full access";
  - question bar "Always for this project";
  - ion-down screen "ion isn't running" with "Start it with: ion daemon start" and a "Try again" button.
- **Looks:** the spec's dark tokens exactly (`--bg #07080A`, `--side #101113`, `--win #131417`, `--accent #7D93FF`, `--good #4CC892`, `--bad #FF6B63`, `--wait #F0AE4C`, radii 6/8/12/16; Sora, Inter, JetBrains Mono). Fonts are bundled; nothing is loaded from the network.
- **Agent text is rendered as Markdown without raw HTML.** Links open nothing inside the app.
- **CI:** `pnpm check` builds the UI (`vite build`) and runs its tests. The Rust side is checked with `cargo check` when Rust is installed; CI skips it.

## Review Focus

1. **The daemon restarts while the app is open.** The app shows "ion isn't running", retries, and reconnects to the new port and token without a reload. Test in Task 2.
2. **A chat with thousands of events.** The timeline merges message deltas, so the screen stays responsive. Test in Task 3: 5,000 deltas reduce to one message item.
3. **An agent's message holds HTML or a `javascript:` link.** It's shown as text and never run. Test in Task 3.
4. **Answering a question someone already answered in the CLI.** The bar disappears once `need.resolved` arrives, and the daemon's "That's already answered" shows inline. Test in Task 4.
5. **A run starts in a chat that isn't open.** The sidebar moves it to Running and back when it ends, and Needs you updates live. Test in Task 4.

### Task 3: The chat timeline and chat view

**Interfaces:**
- **Produces:** `reduce(items: Item[], e: IonEvent): Item[]`, where `Item` is one of:
  - `{ kind: "you", text }`
  - `{ kind: "agent", text, done }`
  - `{ kind: "work", tools: {name, summary, ok?}[], started, ended? }`

- **Copy** is the same wording as the CLI: "Allowed by ion: …", "Denied by ion: … — reason", "You chose: …", "Answered by ion from your decision on 18 Nov: …", "Worked for 2m 04s".

### Task 5: Changes panel

**Files:**
- Modify `packages/schema/src/api.ts` (`chat.diff`), `apps/daemon/src/workspace/` (`chatDiff`), and `apps/daemon/src/api/commands.ts`.
- Create `apps/desktop/src/chats/ChangesPanel.tsx`.

**Interfaces:**
- **Produces:** `chat.diff { chatId } → { files: { path, added, removed, patch }[] }`. It covers everything the chat changed since its worktree was made: the commits on its branch since the merge base with the project's HEAD, plus uncommitted changes.
